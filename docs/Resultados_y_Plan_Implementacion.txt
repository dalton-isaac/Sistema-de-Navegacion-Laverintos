1. PLAN DE IMPLEMENTACIÓN Y ARQUITECTURA DEL SISTEMA
================================================================================

1.1. CONTEXTO Y OBJETIVOS:
-------------------------
El proyecto simula un robot de rescate autónomo en un edificio siniestrado
representado por una cuadrícula bidimensional de tamaño M x N.
- 'S' (Start): Punto de entrada o despliegue del robot rescatista.
- 'G' (Goal): Posición de la víctima o salida de emergencia.
- '0': Pasillo o espacio libre transitable.
- '1': Escombros, losas caídas o paredes infranqueables.

Objetivo General:
Diseñar, implementar y evaluar un sistema integral para resolver laberintos
utilizando algoritmos de búsqueda no informada (BFS, DFS, UCS) e informada
(Greedy, A*), mostrando visualmente las trayectorias y comparando su desempeño.


1.2. MODELADO DEL ESPACIO DE ESTADOS:
------------------------------------
Formalización matemática mediante una 5-tupla:
  < S, s_0, G, Acciones(s), Transicion(s, a), Costo(s, a, s') >

- Espacio de Estados (S): Pares ordenados (fila, columna) en la matriz [0..M-1, 0..N-1].
- Estado Inicial (s_0): Coordenada donde se ubica 'S'.
- Conjunto Meta (G): Coordenada donde se ubica 'G'.
- Conjunto de Acciones (A): {Derecha, Izquierda, Abajo, Arriba}.
- Transición: T((r, c), (dr, dc)) = (r + dr, c + dc), validando que no sea muro ('1')
  y se encuentre dentro de los límites de la matriz.


1.3. MODELO DE COSTOS ASIMÉTRICOS Y HEURÍSTICA:
-----------------------------------------------
Costos de Movimiento:
  • Movimiento Horizontal (Derecha / Izquierda) : Costo = 1
  • Movimiento Vertical   (Abajo / Arriba)      : Costo = 2

Justificación Técnica:
El costo vertical duplicado (c=2) modela el esfuerzo motriz requerido para vencer
la gravedad en pendientes de escombros o sortear fricción mecánica, permitiendo
diferenciar claramente algoritmos que minimizan longitud en pasos (BFS) de aquellos
que minimizan costo energético real acumulado (UCS, A*).

Heurística de Manhattan (para Greedy y A*):
  h(n) = |x_actual - x_meta| + |y_actual - y_meta|
Propiedades:
  - Admisible: h(n) <= h*(n) (nunca sobrestima el costo real en grilla ortogonal).
  - Consistente: h(n) <= c(n, a, n') + h(n') (cumple desigualdad triangular).


1.4. ARQUITECTURA DE MÓDULOS Y ESTRUCTURAS DE DATOS:
---------------------------------------------------
El código en `ProyectoFinal.py` se organiza en 4 capas desacopladas:

1. Capa Algorítmica Nuclear:
   - `bfs`: Cola FIFO `collections.deque` -> Inserción y extracción en O(1).
   - `dfs`: Pila LIFO basada en listas de Python -> Memoria lineal O(b·m).
   - `ucs`: Cola de prioridad `heapq` (Min-Heap) ordenada por g(n).
   - `greedy`: Min-Heap `heapq` ordenado por h(n).
   - `a_star`: Min-Heap `heapq` ordenado por f(n) = g(n) + h(n).
   * Nota de Optimización: En `heapq` se implementó un contador de desempate:
     `(prioridad, contador, nodo_actual, ruta)` para evitar errores de comparación.

2. Capa de Gestión de Escenarios y Generador:
   - 4 laberintos preconfigurados (Presets).
   - Generador estocástico con validación de solvabilidad garantizada mediante BFS.

3. Capa Gráfica y Visualización (Tkinter):
   - Canvas interactivo para dibujo y edición de muros, inicio y meta con el ratón.
   - Animación paso a paso de la frontera (amarillo) y ruta solución (azul).
   - Slider de velocidad en milisegundos (1 ms a 150 ms) y modo instantáneo.
   - Tarjetas de métricas en vivo y ventana modal de comparación con Treeview.

4. Capa de Benchmarking y Gráficos Estadísticos (Matplotlib):
   - Módulo automatizado para ejecutar los 5 algoritmos y generar gráficos 2x2 en PNG.

4. ANÁLISIS CRÍTICO DE MÉTRICAS Y TRADE-OFFS
================================================================================

1. Espacio de Exploración (Nodos Evaluados):
   - Algoritmos no informados (BFS / UCS): Expanden celdas en todas las direcciones
     de forma radial, desperdiciando recursos en ramas opuestas a la meta.
   - Algoritmo A*: Gracias a la heurística f(n) = g(n) + h(n), focaliza la búsqueda
     hacia el objetivo, reduciendo entre 35% y 50% los nodos explorados frente a UCS.

2. Impacto de Costos Diferenciados (Horizontal=1 vs Vertical=2):
   - BFS minimiza el número de saltos absolutos, pudiendo elegir caminos con más
     tramos verticales si la distancia en celdas es igual.
   - UCS y A* minimizan el costo ponderado acumulado, priorizando tramos horizontales
     más económicos y ahorrando energía motriz al robot de rescate.

3. Recomendación para Robótica de Rescate:
   - A* es el algoritmo óptimo y definitivo para despliegue en campo.
   - Greedy se recomienda como algoritmo exploratorio rápido cuando se requiera
     tiempo de respuesta casi instantáneo en áreas abiertas.

5. GUÍA DE INSTALACIÓN Y EJECUCIÓN
================================================================================

Requisitos:
  - Python 3.8 o superior instalado.
  - Tkinter (incluido por defecto en la instalación de Python para Windows/Linux/Mac).
  - Matplotlib (opcional para exportar gráficos PNG): pip install matplotlib

Comandos de Ejecución:

1. Modo Interfaz Gráfica Interactiva (GUI):
   Abra la terminal en esta carpeta y ejecute:
     python ProyectoFinal.py

   Funcionalidades de la GUI:
   - Seleccionar laberintos de prueba desde el menú desplegable.
   - Generar laberintos aleatorios garantizados con el botón '🎲 Generar'.
   - Dibujar/Borrar muros ('1'), pasillos ('0'), Inicio ('S') y Meta ('G') con el ratón.
   - Resolver con animación visual paso a paso o resolución instantánea.
   - Controlar la velocidad de la animación mediante la barra deslizadora.
   - Presionar '📊 Comparar Todos' para abrir la tabla comparativa y exportar gráficos.

2. Modo Benchmark Automatizado por Consola:
   Para ejecutar las pruebas en terminal y generar las imágenes estadísticas:
     python ProyectoFinal.py --benchmark
